## Two ways to get an animation file
1. **After Effects + Bodymovin** — the intended route. A designer builds it and exports JSON.
2. **Generate it.** Lottie/bodymovin is a documented JSON format, so a script can write one.
   `make-lottie.py` turns the real July figures in `lab-data.js` into five bars:
   ```bash
   python3 make-lottie.py     # -> assets/july.json
   ```

## Minimum usage
```html
<script src="vendor/lottie-5.12.2.min.js"></script>
<script>
  var anim = lottie.loadAnimation({
    container: document.getElementById('lot'),
    renderer: 'svg', loop: false, autoplay: true,
    path: 'assets/july.json'          // or animationData: {…} to inline it
  });
  anim.goToAndStop(anim.totalFrames - 1, true);   // reduced-motion: last frame
</script>
```
`path:` uses fetch. Opening from `file://` needs `--allow-file-access-from-files`; inline the JSON
as `animationData:` if you would rather not.

## The decisive limit — why not for analysis
**The bar lengths are baked at export time.** Nothing reaches the animation at runtime.
In the lab page the picture and the table below it show the same figures and are **not connected**:
edit `lab-data.js` and the table changes while the picture does not. You have to re-run
`make-lottie.py`.

That `make-lottie.py` has to exist at all is the evidence.

## When to reach for it
Onboarding, empty states, mascots, product tours — **pictures nobody has to reason from.**
If the numbers must be seen to change, this is the wrong tool.

## Motion decision

Lottie is appropriate only for a validated `narrative-transition` or `attention-guidance` intent.
Do not use decorative loops; preserve a complete static fallback for the report.
