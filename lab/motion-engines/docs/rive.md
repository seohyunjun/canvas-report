## The one line you must not omit
```js
rive.RuntimeLoader.setWasmUrl('vendor/rive-2.21.6.wasm');
```
Without it the runtime **quietly fetches the wasm from unpkg**, which defeats the point of
vendoring and fails silently offline. It is the first line of the lab page's script.

## Minimum usage
```html
<script src="vendor/rive-2.21.6.js"></script>
<script>
  rive.RuntimeLoader.setWasmUrl('vendor/rive-2.21.6.wasm');
  fetch('assets/demo.riv').then(r => r.arrayBuffer()).then(buf => {
    new rive.Rive({ buffer: buf, canvas: document.getElementById('riv'),
                    autoplay: true, stateMachines: 'State Machine 1' });
  });
</script>
```

## Why no `.riv` is bundled
A Rive file is a **binary the editor produces**. Unlike Lottie's JSON it cannot be hand-written or
generated by a script. So this repository carries the runtime and no asset, and the lab page says
so on screen when the file is absent.

To make one:
1. Create a file at <https://rive.app>
2. Put a shape on the artboard and add a **State Machine** (default name `State Machine 1`)
3. Add Inputs (Number / Boolean / Trigger) if you want — that is the whole point of Rive
4. Export → **Runtime (.riv)** → save as `lab/motion-engines/assets/demo.riv`

## The one genuinely good idea
**The State Machine.** A designer authors states and transitions instead of a linear clip, and the
developer only supplies inputs. If Lottie is a play button, Rive is an interface. That is real
progress.

## When to reach for it
Game UI, interactive mascots, illustrations with state. **Never for an analysis document** — if
1.4 MB buys you one decorative animation, that is precisely what
`references/anti-patterns.md` calls *decorative animation*.

## Motion decision

Use Rive only when `cfg.motion` declares one compatible semantic intent and the interaction improves
understanding. Otherwise render the static fallback; a stateful engine is not itself a justification.
