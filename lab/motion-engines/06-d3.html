D3 — the keyed join, and why marks travel

This is not a report. canvas-report ships one HTML file with zero network requests; this page loads vendor/d3-7.9.0.min.js (280 KB) instead. It also owns the DOM — these are SVG elements, not canvas. It is the worked example for references/external-tools.md § A. Usage: docs/d3.md.

D3 7.9.0 · ISC · 280 KB. The controls above are the whole point. Turn the checkbox off and reorder: the bars stay put and only their labels and lengths change, because the join falls back to array index — the animation then describes nothing. Turn it on and the same reorder makes each bar travel to its new row, because the join is keyed on the series name. That is object constancy, and it is the reason D3 has transitions at all.

GSAP animates elements you already have. D3 animates the relationship between data and elements — including the elements that must appear and disappear, which is what enter and exit are. Neither the canvas-report shell nor any of the three motion engines in this lab has an equivalent: the shell repaints a canvas from scratch, so there is no element to keep constant.
